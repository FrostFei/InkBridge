# 同步设计与恢复

## 数据与分层

- `src/core/types.ts` 定义不依赖 UI 的值、快照、冲突和事务模型。
- `src/core/db.ts` 用 Dexie / IndexedDB 保存工作区、文件版本、删除标记、冲突和事务；所有写入成功后 UI 才显示本地已保存。
- `src/core/merge.ts` 用 `node-diff3` 做三方文本合并。按保留换行的行切分，不格式化未编辑 Markdown，不转换 CRLF、BOM 或末尾换行。
- `src/core/sync.ts` 负责抓取本地快照、合并、提交确认和恢复。`GitRemote` 是可替换的接口，单元测试通过本地模拟实现。
- `src/github/client.ts` 负责 GitHub 协议和响应验证。`src/core/blobCache.ts` 是独立的不可变 blob 下载检查点，下载完一部分后中断，可按 SHA 恢复；它不等于已确认的同步基准。

工作区 ID 隔离 owner/repo/branch；仓库名称不区分大小写，分支和文件路径区分。文件保留 `base`、`baseSha`、`current`、`revision`、`dirty`。删除用 `current=null` 表示；没有下载完成不会生成空文件或删除标记。附件值按 Git blob SHA 比较，缓存 Blob 不算编辑。

## 一次同步

1. 获取该工作区的 Web Lock。重复点击、同来源第二个标签页和人工基准恢复都受同一锁保护。浏览器不支持 Web Locks 时，阻止同步并保留本地编辑；不采用不可靠的内存锁替代。
2. 在 IndexedDB 事务里捕获 L、每个文件 revision 与共同基准提交，持久化同步事务。
3. 读取远端 head H、该提交的完整 tree 和全部支持的 Markdown blob。递归 tree 截断时逐目录回退；如果单目录仍截断、响应缺项、内容损坏、非 UTF-8 或校验失败，则整个快照拒绝确认。
4. 对每个路径比较 B/L/R：一侧不变采用另一侧；双方相同则直接收敛；文本不重叠修改自动合并；同段、同名新增、删除对修改和二进制差异转为持久化冲突。
5. 存在冲突时整个批次暂停远端提交。共同基准、双方原文、人工草稿和选择都保留。再次同步校验本地 revision、远端 head、草稿与选择；过时结果重新呈现，绝不直接上传。
6. 使用 H 的 `base_tree`，只写实际变化的 blob/tree 条目，创建一个父提交为 H 的 commit。删除、新增与重命名在同一提交完成，`.obsidian/`、Canvas、符号链接、子模块和其他未编辑项原样保留。
7. **先把候选 commit SHA 持久化，再更新分支 ref，始终 `force:false`。** 若并发远端提交导致拒绝，重新读取与合并，最多 3 次尝试；无差异不创建空提交。
8. 读取分支和候选提交内容，核实候选已被接纳。随后一个 IndexedDB 事务中更新基准与确认 revision。用户在同步期间继续编辑时，不清除其后续变更：将捕获后新增的编辑再次合并到确认版本，遇到重叠保留额外冲突，避免下次同步误删刚收到的远端内容。

协议依据 [Git trees](https://docs.github.com/en/rest/git/trees)、[Git refs](https://docs.github.com/en/rest/git/refs)、[Git blobs](https://docs.github.com/en/rest/git/blobs)。按完整相关快照校验删除，blob 缓存减少重复正文下载；当前版本每次检查完整 tree，并未实现大型仓库专用的索引／树差异优化。

## 失败与恢复

| 发生位置                             | 下一次同步                                                             |
| ------------------------------------ | ---------------------------------------------------------------------- |
| 初次下载中断                         | 重用 SHA 校验的下载缓存；完整下载前不建立不完整基准                    |
| blob/tree/commit 准备失败            | 没有更新 ref，保留本地；孤立 Git 对象不会出现在分支中                  |
| ref 请求超时                         | 先查候选是否为 head 或祖先，再决定确认或重新比较                       |
| ref 已成功、本地确认前崩溃或配额失败 | 从持久化 SHA 核对远端候选内容，再原子确认；避免重复提交                |
| 冲突处理中刷新                       | 从 IndexedDB 恢复 B/L/R 和草稿；已记住的授权自动恢复，否则重新输入 Token |
| 远端历史重写或基准元数据缺失         | 停止自动提交；导出后显式选择保留本地并重建基准，将同名差异转为人工选择 |

GitHub 比较接口 404 时，祖先查询会安全地遍历后代父提交，最多读取 2000 个；不完整或超过上限时停止，不猜测。人工恢复之前若仍有结果未确认的候选提交，必须先确认候选结果，不能直接清空事务。

确认过的完整事务快照会限量保留，以免每次前台检查复制全库而耗尽空间。冲突记录与尚未确认的候选提交不会因普通清理丢弃。浏览器仍可能清理站点数据，持久化存储许可与配额取决于浏览器策略；参见 [WebKit 存储政策说明](https://webkit.org/blog/14403/updates-to-storage-policy/)。

## 兼容性边界

- 当前支持 `.md` / `.markdown` 与代码中 `isSupported` 列出的常用图片、PDF、音视频和 ZIP 附件。未支持文件只保留在远端，导出不包含它们。
- 笔记必须是有效 UTF-8；无效编码阻止完整初始化，需要先在电脑确认转换。Git Blob API 单文件限制、API 限流和浏览器内存限制同样适用。
- 重命名的本地表示是删除与新增，不声称能够可靠识别所有跨设备重命名。UI 提醒受影响链接；当前不自动改写链接。
- 支持常用 wiki / 相对链接、别名、标题、标签、frontmatter 和常用嵌入；重名选择完整路径，不执行 Obsidian 插件。
- 搜索扫描本地已下载笔记，不依赖网络；大库尚未做真实设备性能基准。完整 ZIP 在内存生成，超大库建议分库并定期同步。
- 没有后台持续同步、跨源标签锁、原生目录访问或 iPad Obsidian 沙盒访问。跨设备并发通过 GitHub 非强制 ref 更新处理。
