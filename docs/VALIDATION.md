## 真实测试仓库联调步骤（尚未执行）

1. 由用户明确指定可写的专用测试仓库及已有分支。应用代码仓库与笔记库分开。Token 只在应用内输入，不发送到聊天。
2. 放入 UTF-8 中文/空格路径、大小写不同文件名、带 CRLF/frontmatter 的 Markdown、小图片/PDF、`.obsidian/` 和 Canvas 样本。
3. 首次连接，核对所有支持的正文下载完成；断网重新打开，编辑和新建笔记，下载 ZIP 并核对遗漏附件。
4. 电脑 Git 修改一段、iPad 修改另一段，同步后在电脑拉取；确认双方内容都在。再修改相同段落，分别验证选择版本、保留两份、手动合并。
5. 验证删除对修改、同名新增、附件版本变化和重命名交叉；确认未支持项的 blob/mode 不变、多文件只有一次提交。
6. 两个标签同时同步，推送期间继续输入，断网后恢复；确认待上传计数与内容正确，再同步收敛。
7. 在该测试仓库验证真实 Token 到期、权限不足、限流和分支规则提示。验证失败时，本地笔记、人工草稿与候选事务仍可恢复。

## 已知边界与待验证项

真实 GitHub 写入、分支规则、Cloudflare 发布后响应头、iPad Safari 存储及生命周期行为、大型笔记库性能仍待联调。当前不支持非 UTF-8 笔记、隐藏路径的编辑、自动改写重命名链接、任意 Obsidian 插件、后台持续同步和原生目录访问。下载缓存按不可变 SHA 保留，长期大库使用需关注存储估计；导出 ZIP 在内存生成。

源码、依赖锁文件、构建产物、CI 工作流和部署步骤已提供；CI 工作流尚未在远端 GitHub Actions 执行。发布到公网需用户另行授权。
